## Hvad der er rettet siden runde 10f (din angrebs-spec fulgt: »Målingen skal observere enhver native-start, inklusive --version, uafhængigt af exec.js«)
Ny selvtest-infrastruktur `scripts/v5/exec-tracer.py` (python3 + ctypes ptrace): kører en kommando under PTRACE_TRACEME og følger hele procestræet med PTRACE_O_TRACEFORK|VFORK|CLONE|EXEC|EXITKILL; ved hvert PTRACE_EVENT_EXEC logges `EXEC <pid> <realpath(/proc/pid/exe)> <argv[:8]>`. Ingen syscall-trace (kun exec-/fork-stop) → ~30 ms overhead. Exit-status = kommandoens. Selvtestens `run()` kører nu `python3 exec-tracer.py <log> -- bash codex-run.sh …` og parser loggen til `x.execs`. `startsAf(execs, fil)` = antal distinkte pids der STARTEDE filen: som exe (ELF) eller som shebang-script (kernen viser fortolkeren som exe og scriptet i argv[1] for `#!/bin/bash` hhv. argv[2] for `#!/usr/bin/env node`); kun fortolkere (env/bash/sh/dash/node) tæller — sha256sum/realpath/cmp/timeout med filen i argv er ikke starter. `fixStarts(x)` = starter af native-fixturen (ELF, node-kopi) inkl. `--version`; `fixArgv1(x)` = argv[1] pr. start (rækkefølge).
Assertions (kernel-set, uafhængigt af exec.js og kvittering): forkert native-pin (`wb`) og byttet native (`wg`) → `fixStarts === 0` (F-3h-mutanten »hash efter --version« giver 1 og dør) · positiv kontrol (`w2`) → `fixStarts === 2` med argv[1] = ["--version","exec"] i den rækkefølge, shim-starter 0 · version forkert (`wc`) og flerlinjet (`wh`) → præcis 1 start og den er `--version`, intet exec · grammatik/ELF/tom-lås/node.pin-cases → 0 starter af shim, fixture og node (`startsAf(execs, REAL_NODE) === 0` i n1) · første blok: shim startet præcis 2 gange (ptrace) = samme tal som CALLS-loggen.
